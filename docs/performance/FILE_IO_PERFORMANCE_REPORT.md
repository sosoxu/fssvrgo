# 文件读写与并发性能测试报告

## 1. 结论

本轮新增了可复用的 PostgreSQL + LocalStorage 文件性能测试，独立覆盖 1K、1M、100M 和 1G，分别执行串行写、串行读、4 并发写和 4 并发读。每个组合运行 3 个计时样本，写后校验文件头尾各最多 64KiB，读取校验精确字节数。

针对上一轮发现的问题，本轮将同一路径的并发读合并为共享 namespace lease，并在元数据事务内删除上传 lease，减少 PostgreSQL 往返；namespace lease 获取遇到可识别的临时网络超时时执行有界重试。修复后完整负载 48/48 个样本通过。

修复前完整负载序列为 47/48 成功，1G 并发读出现 PostgreSQL namespace lease TCP I/O timeout。修复后完整负载序列 48/48 成功，所有组合错误率为 0；1G 并发读隔离复测也为 3/3 成功。

本报告测量的是进程内 `FileManager` 调用，不是 HTTP 或 gRPC 端到端测试，因此不能直接用于判定需求文档中的 HTTP/gRPC 1GB 时延目标。

## 3. 测试方法

- 写入调用 `FileManager.UploadFileFromReader`，包含流式暂存、SHA-256、`fsync`、namespace lease/fencing 和 PostgreSQL 元数据提交。
- 读取调用 `FileManager.BeginRead` 获取元数据与共享 namespace lease，再通过 `LocalStorage.OpenReader` 和 256KiB 缓冲流式读取到 `io.Discard`。
- 并发写由 4 个 worker 写入互不相同的文件；吞吐量是 4 个文件的聚合吞吐。
- 并发读由 4 个 worker 同时读取同一文件；吞吐量是 4 个完整文件的聚合吞吐。
- 生成器只保留一个短重复模式，不在内存中构造 1GB `[]byte`。
- 计时不包含测试环境初始化、测试数据准备和写后抽样校验。

## 7. 问题与不足

1. **1G 冷读长尾仍高。** 修复后 1G 并发读 p95 为 34.48s，首轮受磁盘缓存和前序写入影响明显；需要独立冷缓存/热缓存场景和 soak test，不能只看 p50。
2. **并发写没有扩展性。** 100M 的并发写 p50 聚合吞吐比串行写低约 8.2%，1G 低约 7.4%；当前瓶颈主要是共享磁盘持久化、哈希和逐次 `fsync`。
3. **小文件固定开销仍高。** 1K 串行写 p50 为 136.51ms。fencing、事务和 `fsync` 对小文件吞吐占主导，批量提交或安全的 group commit 值得单独评估。
4. **尚未覆盖发布协议门禁。** 本轮没有 HTTP/gRPC、Redis、多实例、加密和 MinIO 数据，不能验证需求中的 HTTP/gRPC 1GB 目标或 10 并发上传门禁。

## 8. 复现方式

完整测试：

```bash
make perf-file-io
```

只复测 1G 并发读：

```bash
make perf-file-io \
  PERF_SIZES=1G \
  PERF_OPERATIONS=concurrent_read \
  PERF_REPORT=/tmp/fssvr-1g-concurrent-read.json
```

可配置项：`PERF_SIZES`、`PERF_OPERATIONS`、`PERF_CONCURRENCY`、`PERF_WARMUPS`、`PERF_SAMPLES` 和 `PERF_REPORT`。

## 9. 验收判断

本轮完成了可重复的服务层文件 I/O 基线和 lease 稳定性修复，完整负载错误率达到 0；但冷读长尾仍明显，且没有覆盖 HTTP/gRPC 固定环境门禁，因此 R-11 仍为“部分完成、待验收”。后续应增加 HTTP/gRPC 端到端 1GB 三轮 p95 门禁和独立冷缓存 soak test。
