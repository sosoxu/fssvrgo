## 实施原则

- 数据完整性和可恢复性优先于减少 Redis 写入次数。
- 未形成真实闭环的能力不得在需求或设计中标记为已实现。
- 本轮本地存储为完整验收后端；MinIO 专属修改和真实 MinIO 集成测试延期。
- 性能优化不得绕过认证、加密、审计或完整性语义。

## 未闭环风险

- R-06：PostgreSQL sequence 分配单调 token，`namespace_fence_heads` 持久化每个最终写路径的最高 token；文件与目录写事务按顺序持有全部层级 shared/exclusive advisory locks，并在 exact-path lock 下推进 head，在存储变更前和提交前校验 holder。较旧 token 即使 holder 仍存活也不能再次提交。LocalStorage 本身仍不会解析 token，且没有跨 PostgreSQL/文件系统事务，因此进程或网络在极窄的存储变更窗口故障时仍不能宣称全局线性一致。
- R-05/R-15：本地单文件覆盖和目录重命名具有进程内失败补偿，但没有持久化操作日志；进程在“存储已移动、DB 未提交”窗口崩溃时仍需启动扫描或事务 outbox 恢复。
- 目录与子文件读写已通过 PostgreSQL 共享/独占层级租约互斥，递归删除元数据使用单事务集合更新；本地目录先原子移到可回滚备份再提交，避免提交后旧清理误删新文件。MinIO 仍是提交后逐对象清理，不是跨对象存储和数据库的全局原子事务。
- R-17：逐块 `fsync` 保证成功响应后的数据持久性，但会增加小块写延迟；在不削弱确认语义的前提下，需要 WAL/组提交后才能安全优化。
- R-09：HTTP 变更类成功操作与失败响应、gRPC 成功/失败请求已覆盖；HTTP 读取类成功请求未完整覆盖，且缓冲满或数据库失败仍可能丢失，需要统一审计中间件与持久化 outbox 才能闭环。
- R-10：HTTP/gRPC 请求、上传大小和当前上传数据请求已接线；锁续期、会话持久化、补偿失败和存储耗时指标仍待补充。
- R-11：已定义验收环境和统计口径，尚未生成固定环境的 1GB 自动门禁报告。
- SQLite 驱动仍保留给隔离功能和方言兼容测试，但服务配置已拒绝 SQLite；旧 SQLite 性能报告不得作为发布验收结论。
- 加密下载仍会先生成完整明文临时文件再响应，虽然内存有界且 Range 正确，但首字节延迟、临时空间和并发大文件性能尚未满足真正边解密边发送的目标。
- 分块下载为保证跨实例完成/读取线性化，每块增加 PostgreSQL 短事务和共享会话状态读写；100MB 本机 3 个单次样本的中位数仍超过 500MB/s，但样本存在明显抖动，固定环境 1GB p95 门禁尚未完成。
- R-13：本机没有 MinIO，所有 MinIO 专属结论保持未验收。
